# 01 · Leyes de UX (psicología del diseño)

Fuentes: video "Las 12 LEYES que TODO DESARROLLADOR debería CONOCER" (Soy Dalto) + [laws-of-ux.com](https://lawsofux.com) (Jon Yablonski).

> El buen diseño se basa en **cómo funciona el cerebro humano**, no en modas visuales.

## Las 12 leyes esenciales

| Ley | Qué dice | Aprendizaje accionable |
|---|---|---|
| **Prägnanz** (simplicidad) | El cerebro prefiere la interpretación más simple. | Simplifica. Formas claras, jerarquía obvia, sin elementos de más. |
| **Hick** | Más opciones = más tiempo y ansiedad para decidir. | Reduce opciones por pantalla. Agrupa o usa progressive disclosure. |
| **Tesler** (conservación de complejidad) | La complejidad no desaparece, solo se traslada. | Asume complejidad en el código para que el usuario tenga simplicidad. |
| **Proximidad** (Gestalt) | Elementos cercanos se perciben como grupo. | Agrupa lo relacionado con espacio. El espacio en blanco es tu aliado. |
| **Posición serial** | Recordamos mejor el primero y el último. | Pon lo importante al inicio y al final de listas/menús. |
| **Fitts** | Tiempo de alcance = distancia + tamaño (inverso). | Botones grandes y accesibles. Acciones frecuentes cerca del pulgar. Tab bar abajo. |
| **Parkinson** | Las tareas se expanden hasta llenar el tiempo disponible. | Usa límites de tiempo, progress bars, deadlines suaves. |
| **Von Restorff** (aislamiento) | Lo diferente destaca y se recuerda. | Resalta errores, notificaciones y CTAs con color/tamaño/contraste. |
| **Pareto (80/20)** | El 80% de efectos vienen del 20% de causas. | Arregla primero los pocos flujos/bugs que causan más frustración. |
| **Zeigarnik** | Recordamos mejor las tareas incompletas. | Progress indicators, guardado automático, estados "en progreso". |
| **Miller (7±2)** | La memoria de trabajo maneja ~5-9 items. | Limita opciones por pantalla. Agrupa en categorías (chunking). |
| **Jakob** | Esperan que tu app funcione como las que ya usan. | Sigue convenciones estándar. No reinventes la rueda sin razón. |

## Leyes extra muy útiles (Laws of UX)

- **Aesthetic-Usability Effect**: lo bonito se percibe como más usable → cuida el pulido aunque ya funcione.
- **Peak-End Rule**: juzgamos una experiencia por su pico y su final → cuida onboarding y el momento de completar.
- **Doherty Threshold**: respuestas < 400 ms se sienten fluidas → optimiza rendimiento, lazy load, caché, animaciones suaves.
- **Cognitive Load**: no sobrecargues → menos texto, pasos y decisiones simultáneas.
- **Paradox of the Active User**: nadie lee manuales → que sea obvio cómo usarla desde el primer segundo.
- **Postel's Law**: sé flexible recibiendo datos (tolera errores del usuario), estricto enviando.

## Prioridad
Si solo aplicas 4: **Jakob + Hick + Fitts + Gestalt (Proximidad)** cubren la mayoría de problemas comunes.
